= Configurer un cluster extensible pour un domaine de gestion VCF à l'aide de MetroCluster
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ../media/


[role="lead"]
Ce cas d'utilisation décrit la procédure de configuration d'un cluster étendu pour le domaine de gestion VMware Cloud Foundation (VCF) en utilisant ONTAP MetroCluster avec FC, iSCSI, NVMe-oF, NFSv3 ou NFSv4.1 comme datastore principal. VCF offre une flexibilité sur les options de déploiement selon vos besoins. L'outil VCF Installer est utilisé pour déployer un nouveau domaine de gestion VCF ou convertir un environnement vSphere existant en domaine de gestion VCF. Dans ce document, nous nous concentrerons sur la partie MetroCluster et nous renverrons à d'autres documentations selon les étapes de déploiement.

image:vmw-vcf-vmsc-mgmt-mcc-001.png["Domaine de gestion VCF avec vMSC, largeur = 500"]



[[introduction]]
== Introduction

Dans cette solution, nous allons démontrer comment implémenter un domaine de gestion VCF étendu avec ONTAP MetroCluster comme principal datastore. MetroCluster permet de déployer une solution de haute disponibilité pour toutes les charges de travail exécutées sur le cluster ONTAP. Si vous devez déployer une solution de haute disponibilité spécifique à certaines charges de travail, envisagez d'utiliser SnapMirror active sync (SAN et NAS). SnapMirror active sync (SAN) fonctionne au niveau du groupe de cohérence, tandis que SnapMirror active sync (NAS) fonctionne au niveau de la SVM. Pour plus d'informations, consultez link:vmw-vcf-vmsc-mgmt-smas.html["Configurez un cluster étendu pour un domaine de gestion VCF à l'aide de SnapMirror Active Sync (SAN et NAS)"].



[[prerequisites]]
== Prérequis

Ce scénario nécessite les composants et configurations suivants :

* Configuration ONTAP MetroCluster prise en charge
* Machine virtuelle de stockage (SVM) configurée avec le protocole de stockage préféré.
* Une interface logique (LIF) a été créée pour acheminer le trafic de stockage et est associée à la SVM.

[[deployment-steps-for-greenfield-vcf-management-domain-with-metrocluster]]
== Étapes de déploiement pour un domaine de gestion VCF Greenfield avec MetroCluster

Pour un déploiement Greenfield (nouveau déploiement sans composants VCF existants), l'outil VCF Installer est utilisé pour déployer le domaine de gestion. VMFS sur FC et NFSv3 sont pris en charge dans ce scénario.

En cas de VMFS sur FC, veuillez consulter link:vmw-vcf-mgmt-principal-fc.html["Domaine de gestion VCF avec un datastore VMFS basé sur FC sur ONTAP comme stockage principal"] pour plus d'informations. Pour NFSv3, veuillez consulter link:vmw-vcf-mgmt-principal-nfs.html["Domaine de gestion VCF avec un datastore NFSv3 sur ONTAP comme stockage principal"] pour plus d'informations.



[[deployment-steps-for-brownfield-vcf-management-domain-with-metrocluster]]
== Étapes de déploiement pour le domaine de gestion VCF Brownfield avec MetroCluster

Un déploiement brownfield est un scénario où vous disposez d'un environnement vSphere existant et que vous souhaitez le faire converger en un domaine de gestion VCF.

Pour iSCSI, NVMe-oF et NFSv4.1, il doit être configuré avec vCenter (de préférence avec ONTAP tools), puis utiliser l’outil d’installation VCF pour l’intégrer au domaine de gestion. Pour plus d’informations, consultez link:vmw-vcf-mgmt-vmfs.html["Convergence de vCenter avec le datastore VMFS"] et link:vmw-vcf-mgmt-nfs.html["Convergence de vCenter avec le datastore NFS"].
