= Configurez un cluster étendu pour un domaine de gestion VCF à l'aide de SnapMirror Active Sync (SAN et NAS)
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ../media/


[role="lead"]
Dans ce cas d’utilisation, nous décrivons la procédure d’utilisation des ONTAP tools for VMware vSphere pour configurer un cluster extensible pour un domaine de gestion VCF.  Cette procédure inclut le déploiement des hôtes vSphere et de vCenter Server, l'installation des outils ONTAP , la protection des banques de données avec SnapMirror Active Sync, la migration des machines virtuelles vers des banques de données protégées et la configuration du stockage supplémentaire.

image:vmw-vcf-vmsc-mgmt-smas-001.png["Cluster extensible avec ONTAP pour le domaine de gestion VCF"]

Les configurations de clusters étendus uniformes et non uniformes sont prises en charge pour SAN. En cas de NAS, il s'agit d'une configuration active-passive avec ONTAP 9.19.1.

[NOTE]
====
Les paramètres de proximité de l'hôte sont utilisés avec la configuration multipath pour garantir la sélection du chemin optimal pour le trafic de stockage. Les paramètres de proximité de l'hôte sont configurés sur l'igroup dans le cas de SCSI et sur le sous-système dans le cas de NVMe-oF. Par exemple, dans une configuration d'accès uniforme à l'hôte, l'hôte a accès aux deux systèmes de stockage du cluster étendu. En configuration multipath, les chemins optimaux et non optimaux sont configurés en fonction des paramètres de proximité de l'hôte.

====


[[scenario-overview]]
== Aperçu du scénario

La solution de cluster étendu peut être implémentée sur le cluster par défaut ou sur un cluster supplémentaire dans les domaines de gestion ou de charge de travail VCF. ONTAP tools 10.6 prend en charge la protection des datastores avec SnapMirror active sync pour les datastores VMFS sur les protocoles iSCSI et FC. ONTAP prend en charge SnapMirror active sync pour SAN (avec iSCSI, FC, NVMe-oF) et NAS (NFS v3 et NFSv4.1). Pour les protocoles SAN, la protection est effectuée au niveau du groupe de cohérence, tandis que pour NAS, elle est effectuée au niveau de la SVM. Le schéma suivant illustre la solution de cluster étendu pour un domaine de gestion VCF avec ONTAP tools pour VMFS avec FC.

image:vmware-vcf-asa-mgmt-stretchcluster-002.png["Cluster extensible avec ONTAP pour le domaine de gestion VCF"]

.Stockage principal sur le domaine de gestion
[%collapsible%open]
====
. Déployez le domaine de gestion VCF avec n'importe quel protocole pris en charge.
+
.. Pour VMFS sur FC et NFSv3, l'outil VCF Installer est utilisé directement. Dans le cas d'iSCSI, NVMe-oF et NFSv4.1, il doit être configuré avec vCenter puis utiliser l'outil VCF Installer pour déployer le domaine de gestion. Pour plus d'informations, consultez link:vmw-vcf-migrate.html["Déploiement du domaine de gestion VCF avec iSCSI, NVMe-oF et NFSv4.1"]


. Déployer les ONTAP tools for VMware vSphere
. Déployer le plug-in SnapCenter pour VMware vSphere (facultatif)
. Protégez le datastore.
+
.. Pour iSCSI et FC, ONTAP tools 10.6 ou version supérieure est utilisé pour protéger les datastores. Dans le cas de NVMe-oF et NFSv4.1, utilisez System Manager pour protéger les datastores. Pour référence, consultez la démonstration vidéo ci-dessous pour NVMe/TCP et NFS.




====
.Stockage supplémentaire sur le domaine de gestion
[%collapsible%open]
====
Une fois le domaine de gestion opérationnel, des banques de données supplémentaires peuvent être créées à l'aide des ONTAP tools 10.6 ou version ultérieure et protégées avec SnapMirror active sync pour iSCSI et FC. Pour NVMe-oF et NFS, consultez la démonstration vidéo ci-dessous, car la démonstration est réalisée sur un domaine de charge de travail, mais les mêmes étapes peuvent être suivies pour le domaine de gestion également.

====
