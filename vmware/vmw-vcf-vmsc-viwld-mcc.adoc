= Configurez un cluster étendu pour un domaine de charge de travail VCF à l'aide de MetroCluster

:allow-uri-read: 
:nofooter:

[role="lead"]
Ce cas d'utilisation décrit la procédure de configuration d'un cluster étendu pour le domaine de charge de travail VMware Cloud Foundation (VCF) en utilisant ONTAP MetroCluster avec FC, iSCSI, NVMe-oF, NFSv3 ou NFSv4.1 comme datastore principal. VCF offre une flexibilité de déploiement selon vos besoins. L'outil VCF Ops est utilisé pour déployer un nouveau domaine de charge de travail VCF ou importer un environnement vSphere existant dans un domaine de charge de travail VCF. Dans ce document, nous nous concentrerons sur la partie MetroCluster et nous renverrons à d'autres documentations selon les étapes de déploiement.

image:vmw-vcf-vmsc-viwld-mcc-001.png["Domaine de charge de travail VCF avec vMSC, width=500"]



[[introduction]]
== Introduction

Dans cette solution, nous allons démontrer comment implémenter un domaine de charge de travail VCF étendu avec ONTAP MetroCluster comme datastore principal. MetroCluster permet de déployer une solution de haute disponibilité pour toutes les charges de travail exécutées sur le cluster ONTAP. Si vous devez déployer une solution de haute disponibilité spécifique à certaines charges de travail, envisagez d'utiliser SnapMirror active sync (SAN et NAS). SnapMirror active sync (SAN) fonctionne au niveau du groupe de cohérence, tandis que SnapMirror active sync (NAS) fonctionne au niveau de la SVM. Pour plus d'informations, consultez link:vmw-vcf-vmsc-viwld-smas.html["Configurez un cluster étendu pour un domaine de charge de travail VCF à l'aide de SnapMirror Active Sync (SAN et NAS)"].



[[prerequisites]]
== Prérequis

Ce scénario nécessite les composants et configurations suivants :

* Configuration ONTAP MetroCluster prise en charge
* Machine virtuelle de stockage (SVM) configurée avec le protocole de stockage préféré.
* Une interface logique (LIF) a été créée pour acheminer le trafic de stockage et est associée à la SVM.

[[deployment-steps-for-greenfield-vcf-workload-domain-with-metrocluster]]
== Étapes de déploiement pour un domaine de charge de travail VCF Greenfield avec MetroCluster

Pour un déploiement Greenfield (nouveau déploiement sans composants VCF existants), l'outil VCF Ops est utilisé pour déployer le domaine de charge de travail. VMFS sur FC et NFSv3 sont pris en charge dans ce scénario.

En cas de VMFS sur FC, consultez link:vmw-vcf-viwld-principal-fc.html["Domaine de charge de travail VCF avec un datastore VMFS basé sur FC sur ONTAP comme stockage principal"] pour plus d'informations. Pour NFSv3, consultez link:vmw-vcf-viwld-principal-nfs.html["Domaine de charge de travail VCF avec un datastore NFSv3 sur ONTAP comme stockage principal"] pour plus d'informations.



[[deployment-steps-for-brownfield-vcf-workload-domain-with-metrocluster]]
== Étapes de déploiement pour un domaine de charge de travail VCF Brownfield avec MetroCluster

Un déploiement brownfield est un scénario où vous disposez d'un environnement vSphere existant et que vous souhaitez l'importer en tant que domaine de charge de travail VCF.

Pour iSCSI, NVMe-oF et NFSv4.1, il doit être configuré avec vCenter (de préférence avec les outils ONTAP), puis utiliser l’outil VCF Ops pour l’importer en tant que domaine de charge de travail. Pour plus d’informations, consultez link:https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1/building-your-private-cloud-infrastructure/working-with-workload-domains/import-an-existing-vcenter-to-create-a-workload-domain.html["Importez un vCenter existant pour créer un domaine de charge de travail"].
