= Utilisez un datastore NFS sur ONTAP comme stockage principal pour un domaine de charge de travail VCF
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ../media/


[role="lead"]
Ce cas d'utilisation décrit la procédure de configuration d'un datastore NFS sur ONTAP comme solution de stockage principale pour un domaine de charge de travail VMware Cloud Foundation (VCF). Cette procédure récapitule les composants requis, les étapes de configuration et le processus de déploiement.



[[benefits-of-nfs]]
== Avantages du NFS

*Simplicité et facilité d'utilisation :* NFS est simple à configurer et à gérer, ce qui en fait un excellent choix pour les environnements qui nécessitent un partage de fichiers rapide et facile.

*Évolutivité :* l'architecture d'ONTAP permet à NFS d'évoluer efficacement, prenant en charge les besoins croissants en données sans modifications significatives de l'infrastructure.

*Flexibilité :* NFS prend en charge une large gamme d'applications et de charges de travail, ce qui le rend polyvalent pour divers cas d'utilisation, y compris les environnements virtualisés.



[[scenario-overview]]
== Aperçu du scénario

Ce scénario couvre les étapes de haut niveau suivantes :

* Créer une machine virtuelle de stockage (SVM) avec une interface logique (LIF) pour le trafic NFS
* Vérifiez la mise en réseau de la machine virtuelle de stockage ONTAP (SVM) et qu'une interface logique (LIF) est présente pour transporter le trafic NFS.
* Créez une règles d'export pour autoriser les hôtes vSphere à accéder au volume NFS.
* Créez un volume NFS sur le système de stockage ONTAP .
* Créez un pool réseau pour le trafic NFS et vMotion dans SDDC Manager.
* Mettre en service des hôtes dans vCenter pour une utilisation dans un domaine de charge de travail VCF.
* Déployez un domaine de charge de travail VCF dans VCF Ops en utilisant un datastore NFS comme stockage principal.
* Assurez-vous que l'image du cluster inclut le plug-in NFS NetApp pour VMware VAAI.



NOTE: Cette solution est applicable aux plateformes ONTAP prenant en charge le stockage NFS, y compris NetApp AFF, AFX et FAS.



[[prerequisites]]
== Prérequis

Les composants et configurations suivants sont utilisés dans ce scénario :

* NetApp AFF, AFX ou système de stockage FAS avec une machine virtuelle de stockage (SVM) configurée pour autoriser le trafic NFS.
* L'interface logique (LIF) a été créée sur le réseau IP qui doit transporter le trafic NFS et est associée au SVM.
* Le déploiement du domaine de gestion VCF est terminé et l'interface de VCF Operations Manager est accessible.
* Au moins 2 vSphere hôtes configurés pour communiquer sur le réseau de gestion VCF.
* Adresses IP réservées au trafic de stockage vMotion et NFS sur le VLAN ou le segment de réseau établi à cet effet.



NOTE: Lors du déploiement d'un domaine de charge de travail VCF, VCF vérifie la connectivité au serveur NFS. Cette vérification s'effectue via la carte réseau de gestion sur les hôtes vSphere avant l'ajout de toute carte réseau vmkernel supplémentaire avec l'adresse IP NFS. Par conséquent, il est nécessaire de s'assurer que soit 1) le réseau de gestion est routable vers le serveur NFS, soit 2) une LIF pour le réseau de gestion a été ajoutée à la SVM hébergeant le volume de la banque de données NFS, afin que la validation puisse se dérouler.

Pour plus d'informations sur la configuration des systèmes de stockage ONTAP , reportez-vous aulink:https://docs.netapp.com/us-en/ontap["Documentation ONTAP 9"] centre.

Pour obtenir des informations sur la configuration de VCF, consultez link:https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1.html["Documentation de VMware Cloud Foundation"].

Pour plus d'informations sur l'utilisation de NFS avec les clusters vSphere, reportez-vous aulink:vmw-vvf-overview.html["Guide de référence NFS v3 pour vSphere 8"] .

[[deployment-steps]]
== Étapes de déploiement

Pour déployer un domaine de charge de travail VCF avec un datastore NFSv3 comme stockage principal, procédez comme suit :

.Vérifier la mise en réseau pour ONTAP SVM
[%collapsible%open]
====
Vérifiez que les interfaces logiques requises ont été établies pour le réseau qui transportera le trafic NFS entre le cluster de stockage ONTAP et le Workload Domain.

. Dans ONTAP System Manager, accédez à *Storage VMs* dans le menu de gauche et cliquez sur la SVM à utiliser pour le trafic NFS. Dans l'onglet *Overview*, sous *Network interfaces*, cliquez sur le chiffre situé au-dessus de l'étiquette *NFS*. Vérifiez que les adresses IP LIF requises figurent dans la liste.
+
image:vmw-vcf-viwld-principal-nfs-001.png["Vérifiez les LIF NFS pour SVM"]



Vous pouvez également vérifier les LIF associés à un SVM à partir de l'interface de ligne de commande ONTAP avec la commande suivante :

[source, cli]
----
network interface show -vserver <SVM_NAME>
----
. Vérifiez que les hôtes vSphere peuvent communiquer avec le serveur NFS ONTAP. Connectez-vous à l’hôte vSphere via SSH et effectuez un ping sur la LIF SVM :


[source, cli]
----
vmkping <IP Address>
----

NOTE: Lors du déploiement d'un domaine de charge de travail, VCF vérifie la connectivité au serveur NFS. Cette vérification s'effectue via l'adaptateur de gestion sur les hôtes vSphere avant l'ajout de tout adaptateur vmkernel supplémentaire avec l'adresse IP NFS. Par conséquent, il est nécessaire de s'assurer que soit 1) le réseau de gestion est routable vers le serveur NFS, soit 2) une LIF pour le réseau de gestion a été ajoutée à la SVM hébergeant le volume de la banque de données NFS, afin que la validation puisse avoir lieu.

====
.Créer une politique d'exportation pour le partage du volume NFS
[%collapsible%open]
====
Créez une politique d’exportation dans ONTAP System Manager pour définir le contrôle d’accès pour les volumes NFS.

. Dans ONTAP System Manager, cliquez sur *Storage VMs* dans le menu de gauche et sélectionnez une SVM dans la liste.
. Dans l'onglet *Paramètres*, recherchez *Politiques d'exportation* et cliquez sur la flèche pour y accéder.
+
image:vmw-vcf-viwld-principal-nfs-002.png["Accéder aux politiques d'exportation"]

+
{nbsp}

. Après avoir cliqué sur Ajouter, la fenêtre *Nouvelle règles d'export* s'ouvre. Ajoutez un nom pour la règle, cliquez sur le bouton *Ajouter de nouvelles règles*, puis sur le bouton *+Ajouter* pour commencer à ajouter une nouvelle règle.
+
image:vmw-vcf-viwld-principal-nfs-003.png["Nouvelle politique d'exportation"]

+
{nbsp}

. Renseignez les adresses IP, la plage d'adresses IP ou le réseau que vous souhaitez inclure dans la règle. Décochez les cases *SMB/CIFS* et *FlexCache* et sélectionnez les détails d'accès ci-dessous. Sélectionner les cases UNIX suffit pour l'accès à l'hôte vSphere.
+
image:vmw-vcf-viwld-principal-nfs-004.png["Enregistrer la nouvelle règle"]

+

NOTE: Lors du déploiement d'un Workload Domain, VCF vérifie la connectivité au serveur NFS. Cela s'effectue à l'aide de l'adaptateur de gestion sur les hôtes vSphere avant qu'un adaptateur vmkernel supplémentaire ne soit ajouté avec l'adresse IP NFS. Il est donc nécessaire de s'assurer que les règles d'export incluent le réseau de gestion VCF afin de permettre la validation.

. Une fois toutes les règles saisies, cliquez sur le bouton *Enregistrer* pour enregistrer la nouvelle politique d'exportation.
. Vous pouvez également créer des politiques et des règles d’exportation dans l’interface de ligne de commande ONTAP .  Reportez-vous aux étapes de création d’une politique d’exportation et d’ajout de règles dans la documentation ONTAP .
+
** Utilisez l'interface de ligne de commande ONTAP pourlink:https://docs.netapp.com/us-en/ontap/nfs-config/create-export-policy-task.html["Créer une politique d'exportation"] .
** Utilisez l'interface de ligne de commande ONTAP pourlink:https://docs.netapp.com/us-en/ontap/nfs-config/add-rule-export-policy-task.html["Ajouter une règle à une politique d'exportation"] .




====
.Créer un volume NFS
[%collapsible%open]
====
Créez un volume NFS sur le système de stockage ONTAP à utiliser comme banque de données dans le déploiement du domaine de charge de travail.

. Depuis ONTAP System Manager, accédez à *Stockage > Volumes* dans le menu de gauche et cliquez sur *+Ajouter* pour créer un nouveau volume.
+
image:vmw-vcf-viwld-principal-nfs-005.png["Ajouter un nouveau volume"]

+
{nbsp}

. Ajoutez un nom pour le volume, renseignez la capacité souhaitée et sélectionnez la VM de stockage qui hébergera le volume.  Cliquez sur *Plus d'options* pour continuer.
+
image:vmw-vcf-viwld-principal-nfs-006.png["Ajouter des détails sur le volume"]

+
{nbsp}

. Sous Autorisations d'accès, sélectionnez la stratégie d'exportation qui inclut le réseau de gestion VCF ou l'adresse IP et les adresses IP du réseau NFS qui seront utilisées pour la validation du serveur NFS et du trafic NFS.
+
image:vmw-vcf-viwld-principal-nfs-007.png["Ajouter des détails sur le volume"]

+
+ {nbsp}

+

NOTE: Lors du déploiement d'un domaine de charge de travail VCF, VCF vérifie la connectivité au serveur NFS. Cette vérification s'effectue via la carte réseau de gestion sur les hôtes vSphere avant l'ajout de toute carte réseau vmkernel supplémentaire avec l'adresse IP NFS. Par conséquent, il est nécessaire de s'assurer que soit 1) le réseau de gestion est routable vers le serveur NFS, soit 2) une LIF pour le réseau de gestion a été ajoutée à la SVM hébergeant le volume de la banque de données NFS, afin que la validation puisse se dérouler.

. Il est également possible de créer des volumes NFS via l'interface de ligne de commande ONTAP. Pour plus d'informations, consultez la documentation des commandes ONTAP pour la commande link:https://docs.netapp.com/us-en/ontap-cli/volume-create.html["création de volume"].


====


[[vcf-workload-domain-default-cluster]]
=== Domaine de charge de travail VCF - Cluster par défaut

Une fois le domaine de gestion opérationnel, le domaine de charge de travail VCF peut être créé :

* Utilisez l'interface utilisateur VCF Ops. Les hôtes vSphere sont mis en service dans vCenter et le pool réseau est configuré. Utilisez System Manager ou l'API ONTAP pour exporter le volume NFS vers les hôtes vSphere.
* Importez un environnement vSphere existant en tant que nouveau domaine de charge de travail. Les ONTAP tools for VMware vSphere, System Manager ou l'API ONTAP peuvent être utilisés pour déployer le datastore NFSv3 ou NFS4.1 sur le cluster vSphere.




[[vcf-workload-domain-additional-cluster]]
=== Domaine de charge de travail VCF - Cluster supplémentaire

Pour étendre le domaine de charge de travail avec un cluster supplémentaire, reportez-vous à https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1/building-your-private-cloud-infrastructure/working-with-workload-domains/expand-a-workload-domain/add-a-cluster-to-a-workload-domain-using-the-sddc-manager-ui.html["Ajouter un cluster SDDC à un domaine VCF"].

Voici les étapes principales pour ajouter un cluster supplémentaire au domaine de charge de travail : * Assurez-vous que les hôtes sont commissionnés et que les pools réseau sont configurés dans vCenter. * Un volume NFS est provisionné sur le système de stockage ONTAP et exporté vers les hôtes du cluster supplémentaire. * Le volume NFS est monté sur l’un des hôtes vSphere du cluster supplémentaire. * Créez un nouveau cluster SDDC dans le domaine de charge de travail sur vCenter et suivez l’assistant pour ajouter le cluster supplémentaire au domaine de charge de travail.
