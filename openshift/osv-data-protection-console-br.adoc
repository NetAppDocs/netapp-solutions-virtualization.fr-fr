= Sauvegarder et restaurer des VM à l'aide de NetApp Console Backup and Recovery Service
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ../media/


[role="lead"]
Sauvegardez et restaurez des machines virtuelles dans Red Hat OpenShift Virtualization à l'aide de la NetApp Console. Cette procédure explique comment créer et gérer des opérations de sauvegarde et de restauration via le service Backup and Recovery Service via la NetApp Console, en utilisant un conteneur Azure Blob Storage comme cible de sauvegarde.

NetApp Console permet la gestion centralisée du stockage et des services de données dans les environnements sur site et cloud. Elle offre un contrôle unifié, une simplicité opérationnelle et une gestion sécurisée. Plusieurs services de données et fonctionnalités de gestion sont accessibles depuis l’interface utilisateur à link:https://console.netapp.com["console.netapp.com"^]. Pour des informations complètes sur NetApp Console, consultez link:https://docs.netapp.com/us-en/console-family/["Documentation NetApp Console"].

Cette section est consacrée au service de données NetApp Backup and Recovery pour les charges de travail Kubernetes, en particulier les machines virtuelles OpenShift. Le service NetApp Backup and Recovery vous permet de découvrir, gérer, créer et associer des politiques de protection à vos applications et machines virtuelles Kubernetes via une interface unique. Pour un guide complet, consultez link:https://docs.netapp.com/us-en/data-services-backup-recovery/br-use-kubernetes-protect-overview.html["Documentation NetApp Backup and Recovery"].

== Flux de travail de sauvegarde et de restauration

. *Assurez-vous de disposer d'un agent Console*
+
Assurez-vous qu'un agent de console est déployé dans l'environnement où votre OpenShift cluster s'exécute. Pour plus d'informations sur l'installation d'un agent de console, consultez la link:https://docs.netapp.com/us-en/console-setup-admin/concept-agent-install-options.html#agent-console-deploy["NetApp Console Documentation d'installation"].

+
.Afficher un exemple
[%collapsible]
====
Dans la NetApp Console, cliquez sur Déployer l’agent comme indiqué dans la capture d’écran, puis déployez l’agent dans l’environnement où le cluster OpenShift est en cours d’exécution.

Dans cet exemple, nous avons choisi l’option sur site. Copiez l’URL du programme d’installation de l’agent, utilisez la commande curl pour télécharger le programme d’installation de l’agent sur la machine Ubuntu exécutée sur vSphere, puis exécutez le programme d’installation pour déployer l’agent Console.

Enregistrez-le en utilisant l'adresse IP de l'agent dans l'URL. Consultez link:https://docs.netapp.com/us-en/console-setup-admin/task-install-agent-on-prem-ova.html["la documentation"] pour des instructions détaillées. Une fois l'agent enregistré, vous pouvez le voir dans NetApp Console comme illustré dans la capture d'écran ci-dessous.

. *Configurez un conteneur Azure Blob Storage comme cible de sauvegarde pour un scénario de sauvegarde et de restauration pour les machines virtuelles OpenShift.*
+
Dans cet exemple, nous utilisons Azure Blob Storage comme cible de sauvegarde. Vous pouvez également utiliser AWS S3, Google Cloud Storage, StorageGRID ou le stockage d’objets ONTAP comme cibles de sauvegarde.

+
Pour plus de détails, consultez link:https://docs.netapp.com/us-en/data-services-backup-recovery/br-start-setup.html#prepare-the-backup-destination["Documentation NetApp Console"].

+
Pour identifier le conteneur Azure Blob Storage comme cible de sauvegarde dans la NetApp Console, vous aurez besoin des informations suivantes depuis le portail Azure.

+
[listing]
----
Application (Client) ID:
Client Secret:
Directory (tenant) ID:
----
+
Pour obtenir ces valeurs, procédez comme suit dans le portail Azure.

+
.. Créez un conteneur de stockage Blob.
.. Créez une application d'entreprise et attribuez-lui les autorisations nécessaires au conteneur de stockage Blob. Récupérez l'ID d'application, l'ID d'annuaire et le secret client de cette application afin de les utiliser dans la NetApp Console pour découvrir le conteneur de stockage Blob Azure comme cible de sauvegarde.
+
.Afficher un exemple

.... Créez un groupe de ressources dans votre abonnement.

. *Dans la NetApp Console, découvrez le cluster OpenShift.*
+
.Afficher un exemple
[%collapsible]
====
Cette étape nécessite que le cluster OpenShift soit en cours d'exécution et que l'agent Console soit déployé dans le même environnement. Suivez ces étapes pour découvrir le cluster OpenShift dans la NetApp Console.

.. Dans la NetApp Console, sélectionnez *Inventory > Kubernetes* et fournissez les détails du cluster OpenShift.
.. Sélectionnez l’agent déployé dans le même environnement où se trouve le cluster OpenShift.
.. Copiez les commandes fournies pour installer Trident Protect et exécutez-les depuis une machine utilisée pour exécuter  `oc` des commandes sur votre OpenShift cluster.
.. Une fois Trident Protect installé avec succès, cliquez sur *Découvrir*. La NetApp Console détecte le cluster OpenShift et toutes ses ressources via l’agent et les affiche dans l’interface utilisateur.

. *Dans la NetApp Console, créez une application pour les machines virtuelles et protégez-les à l'aide de sauvegardes.*
+
.Afficher un exemple
[%collapsible]
====
Dans cette étape, créez une application dans la NetApp Console pour les machines virtuelles qui doivent être protégées. Vous pouvez créer une application pour une seule machine virtuelle ou pour plusieurs machines virtuelles. Vous pouvez également utiliser des espaces de noms pour créer une application afin de protéger toutes les machines virtuelles d’un espace de noms dans le cluster OpenShift.

Vous aurez également besoin d'une stratégie de protection à associer à l'application. Vous pouvez créer une nouvelle stratégie de protection ou en utiliser une existante. Dans cet exemple, une nouvelle stratégie de protection est créée avec l'application et lui est associée. Des sauvegardes sont créées pour l'application en fonction de la stratégie de protection qui lui est associée. Le nombre de sauvegardes conservées dépend de la politique de rétention définie dans la stratégie de protection.

  - groupsnapshot.storage.k8s.io

  - volumegroupsnapshotcontents

  - get
